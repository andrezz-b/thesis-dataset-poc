# AGENTS.md

Proof of concept for an **image QA dataset over Wikidata**: an image of an entity plus a question answered by walking the
Wikidata graph. Example: Nokia 3310 photo + "In which year was this phone's manufacturer founded?"
(`manufacturer P176 → inception P571` → 1865). Details and results: `examples/nokia/README.md`.

## Stack and rules
- JavaScript only (Node 24, ESM, `"type": "module"`). **No Python.** Tool versions are managed by `mise.toml`.
- Wikidata access via `wikibase-sdk` (it only builds URLs; we `fetch` them ourselves with a `User-Agent`, see `lib/wikidata.js`).
  The `wd` CLI (wikibase-cli, configured in `mise.toml`) is fine for ad-hoc checks, but scripts must use the SDK for reproducibility.
- Vector DB: Qdrant (docker). Embeddings: CLIP via `@huggingface/transformers` (runs on CPU in Node).
- Verify claims against live Wikidata; do not trust query patterns from memory (e.g. the phone class is `P31 wd:Q19723444`
  "cell phone model", not `Q17517`).

## Layout
```
config.js         env-driven config object (zod-parsed, defaults); values are set in the [env] section of mise.toml
cli.js            node cli.js list|build|index|query|e2e|docs|all [example...|--all] [--refresh] [--k N]
lib/              shared, example-agnostic: wikidata.js, commons.js (download + attribution), schema.js (zod),
                  registry.js (discovers examples/*), runner.js (build/index/query/e2e), docs.js (READMEs + ATTRIBUTION)
embeddings/       reusable, swappable embedding providers (index.js registry, clip.js)
vector_index/     reusable Qdrant docker-compose, up.sh, qdrant.js wrapper
examples/<id>/    index.js (default export { meta, entities }), src/ helpers, images/, query/, README.md, dist/ (gitignored)
examples/_template/  skeleton for a new example
README.md, ATTRIBUTION.md   generated by `node cli.js docs` from all examples (do not edit by hand)
```
`embeddings/`, `vector_index/` and `lib/` must stay example-agnostic; new examples get their own folder under `examples/`.

## Adding an example
Copy `examples/_template`, set `meta` (id = folder name, name, description, question, goldQuery, goldEntity, queryImage) and
implement `entities(ctx)` returning `Entity[]` (`qid, label, imageUrl, imageFile, role: gold|distractor, extra`); both are
validated by zod (`lib/schema.js`). Put SPARQL/selection logic in `src/`. Write a `README.md` with the `e2e:start/end` markers,
then `node cli.js all <id>`. Generated artifacts (`entities.json`, raw dumps, `e2e.json`) go to `dist/` via `ctx.writeDist`.

## Commands
Everyday tasks are mise tasks wrapping `node cli.js` (`mise tasks` lists them; `[example]` defaults to all examples):
```bash
mise run install
mise run vector:up | vector:down | vector:reset     # Qdrant on :6333
mise run build nokia           # entities -> dist/entities.json, gold query check, images, Commons attribution (--refresh re-runs SPARQL)
mise run index nokia           # embed + upsert into Qdrant (needs vector:up)
mise run query nokia examples/nokia/query/nokia_3310_blue.jpg --k 5
mise run e2e nokia             # query image -> top-k, dist/e2e.json
mise run docs                  # regenerate README.md, ATTRIBUTION.md and the e2e block in each example README
mise run all                   # vector:up, then build + index + e2e for everything, then docs
mise run examples              # list examples
```
Same thing without mise: `node cli.js <list|build|index|query|e2e|docs|all> [example...|--all] [--refresh] [--k N]`.
Commons returns 429 with Retry-After (up to 600s) during bulk download; `build` is resumable, just re-run it.
There is no test suite; the e2e check is reading the e2e table (Nokia 3310 must be rank 1 for the query image).

## Conventions
- Configuration lives in `config.js` (env vars with defaults, documented in `mise.toml` `[env]`; no `.env` file); never read `process.env` elsewhere. Embedder is chosen with `EMBEDDER=<key>` (default `clip-b32`); add providers in `embeddings/index.js`
  (`name`, `dim`, `embedImages`, `embedTexts`, L2-normalised vectors). Collections are named `<example id>__<model>`.
- Qdrant point id = numeric part of the QID; payload is entity-only: `{ qid, label, image }`. Do not put question answers
  (manufacturer, inception year) in the index; ground truth lives in `entities[].extra` (`dist/entities.json`) and `dist/gold_result.json`.
- Images are Wikimedia Commons files kept under `examples/<id>/images/` (committed) as 512px thumbnails, named `<QID>_<file>`.
  Author/licence is stored per entity as `attribution` by `build`; re-run `docs` to regenerate `ATTRIBUTION.md` when images change.
- Keep the Qdrant client and server versions compatible (currently 1.20.x); use `client.query`, not `search`.
- Set a descriptive `User-Agent` on every Wikimedia request and throttle bulk downloads.
- Keep each example README in step with its behaviour; its e2e block is generated by `node cli.js docs`.
