# Nokia Manufacturer Inception Example

Image QA over Wikidata: an **image of a phone** plus the question *"In which year was this phone's manufacturer founded?"*,
answered by walking the Wikidata graph.

| Image | Question | Path | Answer |
|---|---|---|---|
| Nokia 3310 (Q219691) | In which year was this phone's manufacturer founded? | `manufacturer (P176) → inception (P571)` | **1865** (Nokia, Q1418) |

The goal: determine the Nokia phone entity from an image (embedding search), then follow the graph to the manufacturer
and its inception year. Back to the [top-level README](../../README.md).

## Layout

```
index.js            standard example export: meta (name, description, question, gold query, query image) + entities()
src/gold.js         gold SPARQL for Nokia 3310 and the gold entity (label, preferred-rank P18 image, answer)
src/expand.js       SPARQL expansion: phones with an unambiguous answer -> distractor entities
images/             512px Commons thumbnails, named <QID>_<file> (committed)
query/              test query image (committed)
dist/               generated and gitignored: entities.json, gold_result.json, phones_raw.json, e2e.json
```

Downloads, indexing, querying, attribution and docs are shared (`lib/`, driven by `node cli.js`).

## Running

```bash
mise run vector:up
mise run build nokia           # entities (SPARQL), gold query check, images, Commons attribution
mise run index nokia           # embed + upsert into Qdrant
mise run e2e nokia             # query image -> top-k, writes dist/e2e.json
mise run docs                  # regenerate README.md, ATTRIBUTION.md and the e2e block below
mise run all nokia             # vector:up + all of the above
```

`IMAGE_COUNT_NOKIA=10 mise run build nokia --refresh` changes the number of distractors (default `IMAGE_COUNT=25` from `mise.toml`).

## Gold query (`src/gold.js`)

`wikibase-sdk` only builds the URL (`wbk.sparqlQuery`); we `fetch` it with a `User-Agent`.
Result (`dist/gold_result.json`): Nokia (Q1418), inception `1865-05-12` → **1865**.

## Image

The 3310 has two P18 images; the **preferred-rank** one (`Nokia 3310 Blue R7309170 (retouch).png`) is indexed.
The other one (`Nokia 3310 blue.jpg`) is the query image, so the match is not trivial.

## Expansion (`src/expand.js`)

Post-processing in JS: group by phone, drop phones with several manufacturers/inception values or several
images (ambiguous answer), drop unlabeled items, keep the first `IMAGE_COUNT` by QID. The class is `P31 wd:Q19723444`
("cell phone model"). The 3310 is added as the `gold` entity, so the index holds 26 entities by default.
Per-entity ground truth (`manufacturer`, `manufacturerLabel`, `answer`) is kept in `entities[].extra` in `dist/entities.json`,
**not** in the vector index.

## Images

Downloaded as `Special:FilePath/<file>?width=512` thumbnails (~100–400 KB instead of multi-MB originals), magic bytes
verified, existing files skipped (resumable), `Retry-After` honoured.

**Caveat:** Commons rate-limits anonymous bulk downloads aggressively (HTTP 429 with `Retry-After: 600`).
Just re-run `build` until all images are present.

## Embedding + vector index

* **Vector DB: Qdrant** (docker, `vector_index/docker-compose.yml`). One container, cosine HNSW index, arbitrary JSON
  payload next to each vector, dashboard at <http://localhost:6333/dashboard>.
  Point id = Wikidata numeric id, payload = `{ qid, label, image }`, collection `nokia__<model>`.
  Alternatives if real graph traversal next to vectors is needed later: **Neo4j 5**, **Weaviate**, **pgvector**
  (only `vector_index/qdrant.js` would change).
* **Embedding model: CLIP ViT-B/32** (`Xenova/clip-vit-base-patch32`, 512-d, ~90 MB ONNX, CPU in Node via
  `@huggingface/transformers`). It embeds images *and* text into the same space, so text → entity search works later.
  Swap with `EMBEDDER=clip-b16`; new models are registered in `embeddings/index.js`.
