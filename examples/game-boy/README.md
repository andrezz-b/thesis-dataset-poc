# Game Boy Founder Birth Year Example

Image QA over Wikidata: an **image of a Game Boy** plus the question *"In which year was the founder of this console's manufacturer born?"*,
answered by walking the Wikidata graph.

| Image | Question | Path | Answer |
|---|---|---|---|
| Game Boy (Q186437) | In which year was the founder of this console's manufacturer born? | `manufacturer (P176) → founded by (P112) → date of birth (P569)` | **1859** (Nintendo, Q8093 → Fusajirō Yamauchi, Q456052) |

The goal: determine the Game Boy entity from an image (embedding search), then follow the graph to the manufacturer,
its founder and the founder's birth year. Back to the [top-level README](../../README.md).

## Layout

```
index.js            standard example export: meta (name, description, question, gold query, query image) + entities()
src/gold.js         gold SPARQL for Game Boy and the gold entity (label, preferred-rank P18 image, answer)
src/expand.js       SPARQL expansion: electronic device models with an unambiguous answer -> distractor entities
images/             512px Commons thumbnails, named <QID>_<file> (committed)
query/              test query image (committed)
dist/               generated and gitignored: entities.json, gold_result.json, devices_raw.json, e2e.json
```

## Running

```bash
mise run all game-boy        # vector:up + build + index + e2e + docs
```

## Gold query (`src/gold.js`)

Result (`dist/gold_result.json`): Nintendo (Q8093) → Fusajirō Yamauchi (Q456052), born `1859-11-22` → **1859**.

## Image

Game Boy has a single P18 image (`Game-Boy-FL.jpg`), which is indexed. The query image is a different Commons file,
`Game-Boy-Original.jpg`, so the match is not trivial.

## Expansion (`src/expand.js`)

The gold's only class is `P31 wd:Q62008942` ("electronic device model"). Game consoles are spread over several
classes and too few survive the filters (~22), so distractors are drawn from the broad class: **mixed electronic
devices**, not only consoles. Post-processing in JS: group by device, drop devices with several
manufacturers/founders/birth years or several images (ambiguous answer), drop unlabeled items, keep the first
`IMAGE_COUNT` by QID. Per-entity ground truth (`manufacturer`, `founder`, `answer`) is kept in `entities[].extra`
in `dist/entities.json`, **not** in the vector index.
